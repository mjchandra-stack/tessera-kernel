# Per-architecture clippy findings, expected exactly. **Every count is zero**
# (D297), so `tools/ci/arch-lint.sh` fails on the first finding on any port
# rather than tolerating a budget — which is what the file this replaces said
# should happen when a count reached zero.
#
# It got there by taking the sanctioned class seriously rather than counting
# it. `deref_addrof` on `(*(&raw mut STATIC))` was 445 of the 512 findings, and
# it is a lint whose suggested fix does not compile: naming the `static mut`
# directly is `error: creating a mutable reference to mutable static`, denied
# by `static_mut_refs` in edition 2024 — measured by applying the suggestion,
# not assumed. A finding that cannot be taken is not a budget item; it is a
# false positive, and it is allowed at the crate root of each port with that
# reasoning written beside it. The remaining 67 were real and were fixed.
#
# The line per architecture stays, at zero, because it is also the list
# `arch-lint.sh` walks to decide which platforms to lint and which targets must
# be covered. Dropping a line now removes an architecture from the gate; it no
# longer means "this one is clean".
#
# A count may not rise. If a port genuinely acquires a finding that cannot be
# taken, the answer is an `#[allow]` at the site with the reason written down —
# the same discipline `unsafe-inventory.toml` applies — never a number here.
# The history of how the budgets moved between D183 and D297 is in the ledger
# rows that moved them.
